## 中文排版規則

### 空格規則

| 規則 | 正確 | 錯誤 |
|------|------|------|
| 中英文之間加空格 | `使用 Markdown 語法` | `使用Markdown語法` |
| 中文與數字之間加空格 | `共 8 個項目` | `共8個項目` |
| 數字與單位之間不加空格 | `100%`、`5ms` | `100 %`、`5 ms` |
| 全形標點前後不加空格 | `項目，包含` | `項目 ， 包含` |
| 半形標點後加空格 | `item, next` | `item,next` |

### 標點符號

| 情境 | 使用 | 範例 |
|------|------|------|
| 中文句子 | 全形 `，。；：？！（）` | `這是範例，很好。` |
| 英文/程式碼語境 | 半形 `,.;:?!()` | `See example, below.` |
| 中文內引用 | 全形引號 `「」` | `所謂「設計優先」` |
| 列表項結尾 | 不加句號（短語式） | `- 項目一` |
| 列表項結尾 | 加句號（完整句） | `- 這是一個完整的句子。` |

### 段落規範

- 每段 3-5 行，過長則拆分
- 段落間空一行
- 避免一行段落連續出現（合併或用列表）
- 開頭不縮排（Markdown 不支援）

### 專有名詞

保留官方大小寫，不任意修改：

```
✅ GitHub、JavaScript、TypeScript、macOS、iOS、PostgreSQL
❌ github、Javascript、typescript、MacOS、ios、Postgresql
```

## Markdownlint 核心規則

### 空行規則（最常犯）

| 規則 | 說明 |
|------|------|
| MD022 | Heading 前後必須空行 |
| MD031 | Code block 前後必須空行 |
| MD032 | List 前後必須空行 |

```markdown
文字段落。

## 標題

內容段落。

- 列表項一
- 列表項二

下一段文字。
```

### 標題規則

| 規則 | 說明 |
|------|------|
| MD001 | 標題層級遞增（不跳級） |
| MD003 | 統一使用 ATX 格式（`#`） |
| MD025 | 每文件僅一個 H1 |
| MD041 | 文件首行應為 H1（或 frontmatter） |

### 列表規則

| 規則 | 說明 |
|------|------|
| MD004 | 統一使用 `-` 作為列表符號 |
| MD029 | 有序列表統一用 `1.` |
| MD030 | 列表符號後一個空格 |

### 程式碼規則

| 規則 | 說明 |
|------|------|
| MD040 | Code block 必須指定語言 |
| MD046 | 統一使用 fenced style（` ``` `） |

### 其他

| 規則 | 說明 |
|------|------|
| MD009 | 行尾無多餘空格（除了故意的兩空格換行） |
| MD012 | 不超過一個連續空行 |
| MD047 | 檔案結尾必須有一個換行 |

## 文件結構規範

### Frontmatter（選用）

```yaml
---
title: 文件標題
author: 作者
created: 2026-06-05
updated: 2026-06-05
status: draft | review | final
---
```

### 標題命名

- H1：文件名稱，簡短有力
- H2：主要章節，可加一個 emoji
- H3：子章節，不加 emoji
- H4：細項，儘量少用

```markdown
# 系統設計文件

## 🎯 目標

### 功能需求

#### 使用者認證（少用 H4）
```

### 連結風格

- 行內連結：短 URL 直接行內 `[文字](url)`
- 參考連結：長 URL 用參考式 `[文字][ref]` + 底部定義
- 相對路徑：同 repo 檔案用相對路徑 `[文件](./docs/spec.md)`

### 圖片

```markdown
![替代文字](路徑 "標題")
```

- 替代文字必填（無障礙）
- 大圖考慮用 `<details>` 收合

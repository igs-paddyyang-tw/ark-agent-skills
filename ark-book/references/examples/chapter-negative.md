# 反例：同一章寫成「文件」會長什麼樣（不要這樣寫）

下面是 `chapter-golden.md` 同一主題的文件式寫法。結構上它甚至過得了部分 lint，
但它教不會人。每段後面的 `⟵` 標出問題。

---

## role-profile 概述

ark-agent-role-profile 是 ark-agent-skills 中用於定義 agent 人格的 skill，產出 role-profile.yaml，
包含 identity、stance、hard_stops、voice 四個欄位，並內建 17 種角色庫。

⟵ **術語先於例子**：第一句就是「X 是一個用來…的 skill」。讀者還不知道自己為什麼需要它。
⟵ **只給方法不給來歷**：沒有「你會先怎麼做、哪裡撞牆、怎麼辦」。

## 欄位說明

- identity：agent 的身分與職責
- stance：agent 的立場
- hard_stops：agent 不可執行的行為
- voice：agent 的語氣風格

⟵ **流水帳**：四條可以任意換順序，讀完不知道哪個最重要、為什麼。
⟵ **沒有例子**：「agent 的立場」是什麼？沒有一個具體的 qa-worker 讓讀者看見。

## 使用方式

1. 執行 interview.py
2. 編輯產出的 yaml
3. 執行 profile_lint.py
4. 提交至 repo

⟵ **動手做無法執行**：沒有指令、沒有參數、沒有「你應該看到什麼」。讀者照做會卡在第一步。
⟵ **沒有失敗處理**：lint FAIL 了要怎麼辦？

## 注意事項

hard_stops 應謹慎撰寫，避免過多或過少。建議參考角色庫範例。

⟵ **空話**：「謹慎」「避免過多或過少」沒有給任何判準。golden 版給的是「只放做錯會傷人傷錢的事」。
⟵ **沒有誤解段**：讀者最常犯的錯（把流程寫進人格檔、以為 lint 過就等於寫得好）完全沒提。

## 總結

本章介紹了 role-profile 的結構與使用方式。

⟵ **沒有 punchline**：讀者一週後記得什麼？沒有一句可以記。
⟵ **回顧只是重述標題**，不是收斂。

---

## 這份反例過不了的 lint 項目

- 缺 `## 這章要解決的問題`（且沒有問號／「怎麼辦」）
- 缺 `## 路線圖`
- 缺 `[!ASK]`、`[!MYTH]`
- `## 動手做` 沒有 fenced code
- frontmatter 缺 `punchline`（或空）

## 這份反例過得了 lint 但仍不合格的地方（自評清單才抓得到）

- 段落可任意換序
- 沒有一條「因為…所以…」的因果線
- 例子不是讀者自己的專案
- 內容能一字不改地當規格文件用

判斷方式只有一個：把所有「X 是…」開頭的句子刪掉，剩下的能不能教會人。這份反例刪掉後幾乎是空的。

# ark-skills-align v2 設計（落地版）

> 完整研究、外部對照（agentskills.io/Claude plugin/npm lock/release train）與 10 findings
> 逐條分析見 `related_research`。本文件是落地設計:承接 spec 24 AC，定義模組佈局與五 ADR 實作邊界。

## 核心命題

**lint 是門、oracle 是尺、LLM 是手**——「這 agent 手上是哪一版」由 tree hash 對 manifest 判定;
「該不該升」由 tier 策略與 semver 判定;LLM 只讀 notice、跑指令、寫報告。
沿用兩條哲學:**上游做變更就由上游掃消費端**、**沒有收件人的紅燈不做**。

## 契約(references/consumer-contract.md 定義)

- **skills-matrix.yaml**:schema_version/upstream(repo,release,local_clone)/tiers(base same-version,role range,domain none)/agents(role,wave,extra)/pins(version,reason,until)/local_only
- **skills.lock.json**(本機,gitignore):release/synced_at/agents{skill:{version,tree_hash,source,tier,declared_by}}
- **release/manifest.json**:release/commit/skills{version,tree_hash,contract_hash,depends_on,status,replaces,breaking_since}/tiers_default
- **tree_hash**:sha256 於排序後檔案清單(路徑+內容),排除 __pycache__/.pyc
- **semver**:內建最小實作(比較+範圍 >= < ^ ~ *),不引第三方

## 關鍵設計約束（C-1~C-5）

- **C-1** 每 active skill version 是 semver,契約檔變更必伴版號+CHANGELOG,audit 守門
- **C-2** 上游發布單位=release manifest,消費端對齊單位也是它,個別 skill 只能例外 pin
- **C-3** 角色→skill 一份資料(matrix)、sync 邏輯一份(align_sync)、每機一份狀態(lock 不進 git)
- **C-4** 版本感知由套件實例 pull(啟動+每日),heartbeat 回報有人讀的頻道,上游只 major 廣播;判定邏輯只在 skill 腳本
- **C-5** apply 永不無人值守(admin 可 plan/verify,apply 需人明示 exit 10)

## 分工邊界

- **本 skill 擁有**:metadata schema/manifest/matrix/lock 契約、audit AL 規則、align_sync

- **交接 paddy 開發源**:套件 defaults.skills 預設段、scheduler on_start/daily、/api/health.skills、_deploy_skills 讀 lock

# ark-skills-align v2 規格書

## 目標

回答「角色定位完成、agent 已部署後，需求變了/上游 skill 升版了，怎麼把各 agent 手上的
skill 版本對齊」。三支柱:版本基底(semver+manifest+CHANGELOG)、角色分層對齊(matrix+lock+tier)、
版本感知走 pull(套件實例 verify --remote + heartbeat)。

## 已查證缺陷（基準 main，實測）

- **F-1（P0，實測）**:version 僅 21/52、格式不一(`"1.0"`/`"3.0"` 非 semver)、depends_on 14 個無範圍、無 per-skill CHANGELOG
- **F-6（P2，實測）**:腳本分兩家(skill 內 audit/backfill;repo 根 check_consumers/gen_readme/hooks)→ 複本裝到消費端拿不到後者
- **F-7（P2，實測）**:ark-skills-align 無 requirements.txt(兩腳本 import yaml)

## 驗收條件（AC，對齊 5 ADR）

### 版本基底（ADR-001，消 F-1/F-5/F-9）

- **AC-01**:metadata schema v1.2 — active skill `version` 必填 semver;`depends_on` 允許 `{name, version 範圍}`;`contract_files` 選填(缺省 scripts/**、schemas/**、references/*contract*.md、*schema*.md、hooks/**)
- **AC-02**:`backfill_metadata.py --versions` — `x.y`→`x.y.0`、缺者 `1.0.0`;depends_on 字串→物件(範圍 `*`)
- **AC-03**:per-skill `CHANGELOG.md`(Keep a Changelog),major bump 必有 `### Breaking` + 遷移指引
- **AC-04**:`gen_manifest.py` 產 `release/manifest.json`(每 skill:version/tree_hash/contract_hash/depends_on/status/replaces)+ `release/index.json`(tree_hash→版本反查),tag `skills-YYYY.MM-rN`
- **AC-05**:audit findings 穩定規則 ID(`AL-xxx`),exit 0/1/2,`--json` 不用執行序號

### audit v2 規則（ADR-001，消 F-5）

- **AC-06**:既有 14 條規則賦 AL-001~014(語意不變)
- **AC-07**:AL-101 缺 version/非 semver(過渡期 P2)、AL-102 contract_hash 變但 version 未 bump、AL-103 major 無 Breaking、AL-104 depends_on 無範圍(P2)、AL-105 上游 depends_on 範圍不可滿足(P0,gen_manifest 前置)、AL-106 updated 早於 contract 變更日
- **AC-08**:`gen_manifest.py` 只在 audit P0/P1=0 且 AL-105=0 時允許打 tag

### 消費端契約（ADR-002/003，消 F-2/F-3）

- **AC-09**:`skills-matrix.yaml`(消費端唯一交接檔):upstream.release/tiers/agents(role+wave)/pins(附 reason)/local_only
- **AC-10**:`.kiro/skills.lock.json`(本機狀態,gitignore):agent×skill×version×tree_hash×source×tier×declared_by
- **AC-11**:`align_sync.py` 動詞:plan(--waves,不改檔)/apply(--wave N --yes,exit 10 語意)/verify/migrate/resolve
- **AC-12**:AL-201 pin 不可滿足、AL-202 複本落後(警告)、AL-203 local-drift(lock tree hash≠實際)、AL-204 懸空
- **AC-13**:apply 從 release tag 取檔並以 manifest tree_hash 驗證(非本機 working tree)

### 角色分層（ADR-005）

- **AC-14**:tier 策略 — base(same-version,major 不一致 AL-301 P0、minor AL-302 P1)、role(range 預設 ^major)、domain(none)
- **AC-15**:AL-303 同 agent 內 depends_on 範圍不滿足、AL-304 SOUL 條列≠matrix、AL-305 distill-sources 指向 lock 不存在的 skill
- **AC-16**:`plan --waves` 依 matrix role 排波次(admin→leader→worker),每波 verify P0/P1=0 才下一波

### 版本感知（ADR-004，消 F-4）——套件段為交接項

- **AC-17**:`verify --remote` 取 manifest(預設 GitHub raw,四 repo public 免 token),輸出 lag/breaking/unknown,拉不到退回本機 clone 標 unreachable
- **AC-18**:`heartbeat` 組一行結構化訊息 + /api/health(同版無變化只寫 health)
- **AC-19**:`pre-push` v2 — major/contract_hash/depends_on 變更時廣播 Alignment Notice(既有只管移除)
- **AC-20**:`notice_build.py` 由 --impact JSON 產 md-report review 型,report_lint 過
- **AC-BC-PKG**:套件預設段(defaults.skills)+ scheduler + /api/health.skills 在 paddy 開發源,**列為交接項不在本 repo 執行**

### 套件優化（消 F-6/F-7/F-8/F-10）

- **AC-21**:腳本歸位 — check_consumers/gen_readme/hooks 搬入 skill scripts/,repo 根留 thin wrapper
- **AC-22**:`requirements.txt`(pyyaml)
- **AC-23**:onboarding-gate.md 去 legacy 類別 + taxonomy 名冊門檻;SKILL 引用的檔存在
- **AC-24**:SKILL.md 兩模式(upstream/consumer)重寫瘦身 ≤120 行,敘事移 ops-playbook.md;evals(upstream 3+consumer 3+negative 2);audit 規則 fixtures(每 AL 一 pass 一 fail)

## 向後相容（硬要求）

- **AC-BC-1**:audit 既有 14 條規則語意不變(只賦 AL-ID);exit code 舊只判 !=0 不受影響
- **AC-BC-2**:role-profile 的 `skills: string[]` 字串形式永久相容(v1.2 只新增物件形式)
- **AC-BC-3**:AL-101(version 缺)過渡期 W0-W1 為 P2(不擋),回填後才升 P1
- **AC-BC-4**:check_consumers 既有四掃描面 + 16 測試搬入不回歸
- **AC-BC-5**:未遷移的 team(無 skills-matrix.yaml)→ align 提示 migrate,不報錯

## 執行範圍界定

- **本 repo 可做**:AC-01~16、19~24(上游版本基底 + 消費端契約 + align_sync + audit 規則 + 套件優化)
- **交接項(paddy 開發源)**:AC-BC-PKG(套件 defaults.skills/scheduler/api-health、_deploy_skills 讀 lock)

## 已拍板決策（2026-09-17 grill-me 拷問，8 個開放問題全解）

| # | 開放問題 | 決策 |
|---|----------|------|
| D-1 | fleet 頻道歸屬 | **用既有 team 頻道**（不新開）;`fleet` 概念/命名全改 `team`，`ARK_FLEET_CHAT_ID`→`ARK_TEAM_CHAT_ID` |
| D-2 | apply 授權層級 | **分層 + 私訊 manager 確認**:role/domain 用 L2、base tier major 升級加嚴（對齊 L3） |
| D-3 | base tier 決定權 | **上游預設 + 部署 manager 可在 skills-matrix.yaml 覆寫** |
| D-4 | bot daily 排程 | **用 bot 既有 schedule_engine 掛 daily**（查證:ark_bot_agent 有 scheduler，原「bot 無排程」前提不成立） |
| D-5 | AWS 出口 | **假設可達 + 拉不到標 unreachable**;後續實測 AWS 出口（非阻塞） |
| D-6 | 共用 clone / 離線後備 | **只有本機開發機有全庫 clone**;AWS/AIPC 上網直取、拉不到即 unreachable **無本地後備**;pull 對它們是硬前提 |
| D-7 | tested_against 必填 | **消費端型 skill 必填**（依賴外部工具/套件）;純內部用 depends_on |
| D-8 | unknown 複本 | **一律視為需更新**（排進 plan）;local_only 排除;apply 仍需私訊 manager 確認 |

🔴 **用詞校正（貫穿全設計）**:跑 align / 確認 apply 的是**該部署的 manager 總機 `<專案>-agent`（dir="."）**，
不是 `admin-agent`（那是另一個 role=admin 維運角色，不混）。波次 wave 1 = manager 先升。
🔴 **離線後備非通則**:設計 §5「退回本機 clone」只對本機開發機成立;AWS/AIPC 無全庫 clone，拉不到即 unreachable。

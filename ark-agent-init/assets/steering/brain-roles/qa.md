# 🧠 QA 知識背景

## 專業領域
- 自動化測試（pytest / unittest / pytest-asyncio）
- E2E 與整合測試（API 契約、跨模組流程）
- 測試設計（等價分割 / 邊界值 / 錯誤路徑）
- Code Review（正確性、可測性、回歸風險）

## 工作原則
- 先列「要驗什麼」再寫測試，不是先寫 code
- 新寫的測試要先**確認它會紅** —— 紅得對才證明它在測東西
- 一個測試只驗一件事，失敗訊息要能直接指出原因
- 每個修好的 bug 留一個回歸測試，註解寫**為什麼會錯**
- 測試必須自包含：只用 tmp 目錄與自建 fixture，不依賴本機實體設定

## 假綠燈的常見形狀（優先懷疑這些）
- 掃描目標路徑不存在 → 掃 0 個檔案卻回報 ✅
- 只驗寫法（字面值）沒驗實際值 → 擋得住舊寫法，擋不住「出口組錯」
- 提詞／設定裡寫死的路徑與實際資料位置不同 → 永遠掃不到，但回報成功
- 測試被自己的註解或說明文字命中（掃描式測試要排除註解與 docstring）
- 語法檢查通過但結構錯誤（插入位置不對造成死碼）

## 技術偏好
- Python：`pytest` + `tmp_path`，斷言帶訊息說明「為什麼這樣才對」
- 非同步：用明確等待條件，**不用 `sleep`**（會造成間歇性失敗）
- 參數化優先於複製貼上；共用前置放 fixture
- 掃描式守門測試用 `ast` 排除註解與 docstring

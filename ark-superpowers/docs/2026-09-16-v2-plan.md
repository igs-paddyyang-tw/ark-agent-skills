# ark-superpowers v2 執行計畫

分階段推進，每階段一 commit，以 deterministic 條件放行。
向後相容硬要求：每階段結束既有行為（build_docs new/upgrade、self_check）不回歸。

## W0 — 止血 + 反證先行（AC-01/02/06/21/22）

**目標**：先寫「骨架必 FAIL」fixture（在現況 checker 上跑 → 目前是 PASS，即反證的紅燈方向），
修兩個 P0 的最小面。

- skeleton fixtures：八型 `build_docs.py new` 產物當 fixture
- `render()` 統一 placeholder（消 F-2：new 與 upgrade 共用替換清單，含 `{專案名稱}`/`{Project Name}`/`{Author}`）
- `build_fingerprints.py` + `SP-001 template_residue` / `SP-002 placeholder_token`（先只對模板行做指紋）
- `self_check.sh` 加：`build_docs.py new` 八型斷言零 `{…}` 殘留 + 八型骨架 `doc_lint` exit 2
- 補 `scripts/tests/test_cli_contract.py`（F-11）

**Gate（deterministic）**:
- 八型 new 產物的**工具型 placeholder**（`{名稱}`/`{專案名稱}`/`{Project Name}`/`{作者}`/`{Author}`）零殘留
  —— 這是 F-2 的本質（new 與 upgrade 兩路徑替換清單一致）。
  內容填空 placeholder（`{系統/功能}`/`{階段名稱}` 等，刻意留白給使用者）在 W1 模板 v2 移至 HTML 註解後才使 `grep -c "{"` = 0
- 八型骨架 `doc_lint` 皆 **exit 2**（反證:改前跑現況 checker 是 PASS，證明測試抓得到）
- `self_check.sh` 全過；`test_cli_contract.py` pytest 綠

## W1 — 契約（AC-04/05/07/08）

- `sections.yaml`（取代兩張手工表）+ `id-scheme.md`
- 模板 v2：錨點 `<!-- sec:key -->` + ID 欄 + 範例值移 HTML 註解 + `## 變更紀錄` 節
- `doc_lint.py` 單檔規則 SP-00x~01x、04x + `check_doc_completeness.py` shim
- 重建 `fingerprints.json`（範例值移註解後）

**Gate**:pass fixtures（改寫 v2）exit 0；fail fixtures 各命中預期 SP-ID；
parity（每 key 有 zh+en，模板 H2 集合 = yaml 鍵集合）。

## W2 — 生命週期（AC-11~17）

- `lifecycle.yaml` + `status`/`supersede`/`backfill-ids` 指令 + SP-03x
- ADR 模板升 MADR 4（7 節）+ `index` v2（雙向 supersede 鏈）+ `adr --from-design` 抽取

**Gate**:非法轉移被拒；`approved` 後手改 → SP-032；supersede 後 `_index.md` 顯示雙向鏈；
design 內嵌 ADR fixture → SP-042。

## W3 — 鏈與 intake（AC-09/13/18/19/20）

- `doc_lint --chain`（SP-014/020/021/030/043 + plan 委派 + CF regex 預檢）
- `from-decision` + `intake/*.md` + `--report`（review 型）

**Gate**:decision fixture（5 個 D-x）→ spec 有 5 個 C-x 且 source 一一對應；
`--report` 產物 `report_lint.py` exit 0；validator 對含 CF 規則的 fixture 依賴維度非 N/A。

## W4 — 收斂（AC-23/24）

- SKILL.md 重寫（8 型 + onepager 關係）+ evals 可斷言 + `scripts/tests/`
- `ark-skills-align` 加「skill 引用的測試檔必須存在」規則

**Gate**:`prompt_lint.py --type skill` 無 P0/P1；`audit_skills.py` P0/P1=0；pytest 全過。

## 最終驗收（AC-BC-1~4）

- 向後相容:build_docs new/upgrade 子指令保留、check_doc_completeness shim 可用、
  既有文件 --legacy 過渡、plan 型委派 executor
- 全測試綠 + commit 分階段推

## 依賴注意

- W3 的 plan 委派需 `ark-spec-executor` 的 `plan_lint`（若 executor 未升 v2 → SP-070 degraded 過渡）
- W3 的 CF regex 預檢需 `ark-code-spec-validator` 提供可 import 的規則常數
- 這兩個跨 skill 依賴不阻塞本 skill W0-W2；W3 可先做本 skill 端，跨 skill 部分標 degraded

# ark-superpowers v2 設計（落地版）

> 完整研究、外部對照（MADR 4/spec-kit/OpenSpec/Kiro EARS）與 14 findings 逐條分析見
> `related_research`（claude 研究草案）。本文件是**落地設計**：承接 spec 的 24 AC，
> 定義模組佈局與五項架構決策的實作邊界，供 plan 展開。

## 核心命題

**lint 是門、oracle 是尺、LLM 是手**——文件「像不像規格」由指紋與規則判定(門)；
「規格說了什麼」由 LLM 與人寫(手)；「規格有沒有被實作」交下游 validator(尺)。
v2 把守門從形狀檢查下沉到 deterministic 的指紋+錨點+規則 ID。

## 五項架構決策（對齊 spec AC）

| ADR | 決策 | 落地 | 對應 AC |
|-----|------|------|---------|
| ADR-001 | 守門=模板指紋+章節錨點+SP-xxx | `check_doc_completeness.py`→`doc_lint.py`（shim 保留）；`build_fingerprints.py` 建 `fingerprints.json` | AC-01~06 |
| ADR-002 | 全鏈穩定 ID，build_docs 配號 | `id-scheme.md` 定義前綴；`--chain` 驗參照；`backfill-ids` 補既有 | AC-07~10 |
| ADR-003 | 狀態機+工具維護版本+變更紀錄 | `lifecycle.yaml`；`status`/`supersede` 指令；approved_hash 防手改 | AC-11~14 |

## 單一來源（`references/`）

- `sections.yaml`：型別×語言×章節鍵×必要性×錨點（取代 `REQUIRED_SECTIONS_ZH/_EN` 兩張手工表；parity 改「每 key 有 zh+en」）
- `id-scheme.md`：FR/NFR/C/SC/OQ/DD/CMP/API/ADR/CF 前綴（AC 由 executor 擁有，depends_on 互引）
- `lifecycle.yaml`：status enum×轉移×需要欄位
- `intake/{spec,design,plan}.md`：訪談題庫
- 模板 v2：錨點 `<!-- sec:key -->` + `{…}` placeholder，**範例值移 HTML 註解**（不進指紋）

## 關鍵設計約束（C-1~C-5）

- **C-1** 判「還是模板」用指紋、判「章節在不在」用錨點（不用關鍵字/子字串猜）
- **C-2** 下游會引用的東西都有穩定 ID，與 executor v2 共用一份定義
- **C-3** 狀態/版本/變更紀錄只由工具改，人不手改 frontmatter
- **C-4** 機器要讀的表格/章節都在契約檔標明消費者與格式
- **C-5** 產出路徑只有一條實作（new 與 upgrade 共用 render）

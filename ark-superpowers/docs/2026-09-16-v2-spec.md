# ark-superpowers v2 規格書

## 目標

把 `ark-superpowers` 從「模板生成器」升級為「規格契約引擎」：守門從**形狀檢查**下沉到
**模板指紋 + 章節錨點 + 規則 ID**；文件全鏈有穩定 ID 與生命週期；模板與下游消費者對齊。
向後相容:既有文件走 `--legacy` 過渡,`check_doc_completeness.py` 保留為 shim。

## 已查證的核心缺陷（基準 main@3dfe535，實測附錄 A + 本次獨立驗證）

- **F-1（P0，已實測）**:plan 骨架原樣通過 `check_doc_completeness.py`（🎉 通過）——守門只驗形狀
- **F-2（P0，已實測）**:`build_docs.py spec` 產出 title = `"{專案名稱} 規格文件"`——new 路徑未替換 placeholder，與 upgrade 路徑不一致
- **F-11（P2，已實測）**:`test_cli_contract.py` 被兩處註解引用但不存在（0 測試檔）

## 驗收條件（AC，對齊 design ADR / SP-xxx）

### 守門模型（ADR-001）

- **AC-01**（F-1/F-11）：八型骨架跑 `doc_lint` 皆 **exit 2**（骨架必 FAIL；反證:目前全 PASS）
- **AC-02**（F-1）：`SP-001 template_residue` — 正文行/表格 cell 命中 `fingerprints.json` → P0
- **AC-03**（F-1）：`SP-002 placeholder_token` — `{…}`/`[NEEDS CLARIFICATION]`/`TODO`/`TBD`/`（待填）` → P0
- **AC-04**（F-4）：`SP-004 section_missing` — 必要章節以精確鍵/錨點比對（非子字串），少寫/錯放被抓
- **AC-05**（F-10）：`doc_lint` 輸出規則 ID + 嚴重度 + 位置，exit 0/1/2，`--json`
- **AC-06**（F-1）：`build_fingerprints.py` 掃模板產指紋；指紋落後模板 → exit 2（不靜默用舊指紋）

### 契約化 ID（ADR-002）

- **AC-07**（F-3）：spec 端 `FR-`/`NFR-`/`C-`(`source:D-x`)/`SC-`/`OQ-` 有穩定 ID，由 build_docs 配號
- **AC-08**（F-3）：`SP-010 id_unique/id_sequence` — 同前綴 ID 重號或斷號 → P0
- **AC-09**（F-3）：`doc_lint --chain` 驗參照完整性（D→C、related_* 路徑存在且型別正確 SP-020）
- **AC-10**（F-3）：`backfill-ids` 對既有文件一次性補號（保留舊文字）

### 生命週期（ADR-003）

- **AC-11**（F-5）：`status` enum 依型別定義；轉移只經 `build_docs.py status --to --by`
- **AC-12**（F-5）：`version`/`updated`/`## 變更紀錄` 只由工具改（以 ID 為單位:ADDED/MODIFIED/REMOVED）
- **AC-13**（F-5）：`SP-030 stale_downstream` — design/plan 的 spec_version < spec 目前 version → P1
- **AC-14**（F-5）：`SP-032` — `status:approved` 但內容雜湊 ≠ approved_hash → P0（手改被抓）

### ADR 統一（ADR-004）

- **AC-15**（F-6）：ADR 統一 MADR 4 單一編號空間；架構級決策走 `build_docs.py adr` 建檔
- **AC-16**（F-6）：`SP-040` 選項<2→P0、`SP-041` Consequences 缺 bad→P1、`SP-042` design 內嵌 ADR 標題→P1
- **AC-17**（F-7）：ADR `Confirmation` 章節承載 `CF-x` 機檢規則（validator 依賴維度輸入）

### 資訊收集（ADR-005）

- **AC-18**（F-8）：`from-decision <decision.md>` 確定性把 D-x 逐字寫入 C-x（`source:D-x`）
- **AC-19**（F-8）：`SP-050 clarify_gate` — status≠draft 卻有 blocking OQ 或 `[NEEDS CLARIFICATION]` → P0
- **AC-20**（F-8）：`references/intake/{spec,design,plan}.md` 訪談題庫（每題對應章節鍵+ID 前綴）

### 測試與收斂

- **AC-21**（F-11）：補 `scripts/tests/test_cli_contract.py`（--help 不產檔、非 ASCII 無 --slug exit 1、placeholder 零殘留、非法轉移被拒）
- **AC-22**（F-11）：`self_check.sh` 呼叫 `build_docs.py new` 全型並斷言零 `{…}` 殘留、骨架 exit 2
- **AC-23**（F-14）：evals 改可斷言（骨架 exit 2、from-decision C-x 數=D-x 數、approved 手改被 SP-032）
- **AC-24**（F-9）：SKILL.md 文件類型表列 8 型並說明 onepager 關係

## 向後相容（硬要求）

- **AC-BC-1**：`build_docs.py new/upgrade` 既有子指令與參數保留
- **AC-BC-2**：`check_doc_completeness.py` 保留為 shim（轉呼叫 doc_lint，印棄用警告）三個 wave
- **AC-BC-3**：既有文件走 `doc_lint --legacy`（只跑 SP-001~007，其餘降 P2）過渡
- **AC-BC-4**：plan 型契約不自持有，委派 `ark-spec-executor` 的 plan_lint（未同步升版走 SP-070 degraded）

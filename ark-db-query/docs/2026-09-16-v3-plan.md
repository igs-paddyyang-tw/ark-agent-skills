# ark-db-query v3.0 執行計畫

分階段推進,每階段一個 commit,以 deterministic 條件放行(不以「感覺完成」放行)。
向後相容硬要求:每階段結束 `test_sqlite_contract.py` 必須仍綠。

## W0 — 反證先行（AC-24）

**目標**:先寫抓現有漏洞的測試,證明它們在 v2.0 上是紅的。

- `tests/test_gate_l1.py`:F-01(前置註解繞過)、F-02(巢狀/腳本寫入入口)全案例 → 期望 GATE_BLOCKED
- `tests/test_bq_fake_client.py`:monkeypatch bigquery.Client,驗 F-05(OFFSET 誤補 LIMIT)、F-07(逾時不 cancel)

**Gate**:在 v2.0 程式碼上跑,紅燈數 ≥ 8(證明測試確實抓得到漏洞)。sqlite 契約仍綠。

## W1 — 守門下沉（AC-01~05）

- `gate.py`:L1 allowlist(SELECT/WITH/SHOW/DESCRIBE/EXPLAIN/PRAGMA)+ 註解剝除狀態機(處理 `--`/`/* */`/字串內分號)+ gate_explain
- `bq_client.py`:從 bq_query 抽 get_client/dry_run/estimate/cancel-on-timeout/params;L3 statement_type 判定
- `db_common.guard_read_only` 改呼叫 gate.py;bq_query 改用 bq_client + max_results(不改寫 SQL)

**Gate**:W0 的 test_gate_l1 全綠、test_bq_fake_client 的 F-05/F-07 綠;test_sqlite_contract 仍綠。

## W2 — 資源保護（AC-06~10, 15~18）

- `drivers.py`:連線工廠 + `iter_rows` generator(5 引擎串流)+ L2 read-only session
- `db_export.py`:非 BQ 串流匯出,契約同 bq_export
- `db_common`:契約 v1.1 欄位、exit code 表、stdout 純度(redirect_stdout)、bytes 截斷(--max-stdout-bytes)
- `db_query.py`:瘦身為 CLI 組裝層,driver 移至 drivers.py;`--timeout`→`--connect-timeout`+`--query-timeout`(別名相容)

**Gate**:契約 golden file 通過;10 萬筆 sqlite `SELECT *` 峰值 RSS < 100 MB(先量 v2.0 基線);test_sqlite_contract 仍綠。

## W3 — 多 agent 治理（AC-11~14, 23）

- `ledger.py`:fcntl 檔案鎖、當日累計讀取、預算檢查(BUDGET_EXCEEDED)、稽核追加、fail-closed
- `__version__.py`:SKILL_VERSION = "3.0.0"
- `db_health.py`:改用 drivers 工廠、加 ledger_writable/read_only_session 檢查(修 F-15/F-16)

**Gate**:9 並發各 append 100 行 → 900 行無損;預算攔截測試綠;test_ledger 綠。

## W4 — 文件與稽核（AC-19~22）

- SKILL.md:決策樹加 db_export/budget 分支、守門表更新三層、version 3.0
- troubleshooting.md:加 TIMEOUT/BUDGET_EXCEEDED、刪「取最後一行 JSON」
- gate-matrix.md:各引擎 L1/L2/L3 能力矩陣(揭露 MSSQL 差異)
- bq_schema `--brief`(修 F-14)、mongo `_id` 修正(F-17)、`--password` deprecated(F-18)

**Gate**:audit_skills P0/P1 = 0;prompt_lint 過;gen_readme --check 綠。

## 最終驗收（AC-BC-1~4）

- 向後相容:v2.0 指令列參數全保留、stdout 舊欄位不刪、--out 格式不變、test_sqlite_contract 全綠

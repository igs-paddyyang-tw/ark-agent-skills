## 1. 兩份範本報告的分析

輸入：`金猴爺AI試玩筆記_20261007.html`（手機正式帳號，3 台機台，73 分鐘）與 `金猴爺新手體驗報告_20261008.html`（BlueStacks 新帳號，約 3.5 小時，含閃退重現）。

|---|---|---|---|

### 做法（報告裡寫出來、v2.2 固化成工具的）

1. **截圖 → 看圖判斷 → 點擊**，每一步寫原因（decision-log）。→ `tap --why` 必填、自動寫 decision-log.md。
2. **重複旋轉交給小腳本**，Agent 每隔幾把看截圖。→ `spin --shot-every`，App 掉出前景自動停並存 logcat。
3. **規則都當場讀遊戲內規則頁**，再跟實際對照。→ 探索準則 E1。
4. **每 5–10 把對帳、每次結算對帳**。→ `ledger` 自動算預期 vs 實際。
5. **彈窗分免費 / 付費 / 資訊 / 對外**，付費一律 X。→ `popup --kind`。
6. **安全邊界**：不儲值、不評分、不綁定、不加好友、不更新、不斷主機網路。→ 預設禁止清單（init 印出、報告寫入）。
7. **閃退存 logcat、重現多次、寫差異條件**。→ `logcat`、`finding --repro`、E8。
8. **有效點擊率**：點偏 / 太早 vs 遊戲沒反應分開算。→ `mark --outcome miss|early|noresp`。
9. **大部分問題是清單外自己找到的**（規則 vs 實際、預設勾選、自動續行、點了沒反應）。→ 第二階段自我探索 + `explore-playbook.md`（E1–E16）。

### 範本報告的缺口（v2.2 順便補）

- 點擊數一半是「估計」（06:53 前沒逐筆記錄）→ 改成每次點擊都是事件，全部實測。
- 探索沒有假設紀錄，讀者不知道 AI 試過什麼、哪些沒問題 → 探索表（假設 / 做法 / 結果 / 狀態），`ok` 也列出。
- 發現沒有穩定 ID，跨天難追 → F-/X-/L-/S- ID；`promote` 把發現轉成下一輪回歸項。
- 證據散在 shots/ → 每個判定與發現都必須掛截圖，`report --strict` 檢查。

## 3. 和既有鐵律的關係

v2.1 第四條「執行期不用眼」不變——它管的是 aiqa 自動回歸。playtest 是**準備期 / 探索期**：用眼找問題、走路線，
產出（發現 → `checklist.next.md`、點擊座標 → macro 草稿）再交給 aiqa 變成不用眼的回歸。兩者是一個循環：

```
清單 md ──playtest（用眼）──▶ report.html + checklist.next.md + taps
                                   │                     │
                                   ▼                     ▼
                         aiqa_testgen → checklist.json    macro（record / 編輯）
                                   └──────▶ aiqa_run（不用眼、可重跑）
```
